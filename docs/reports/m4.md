# M4 Report: The full system

**Finished:** 2026-10-11

## The project, in two lines

A system that studies the Indian share market each evening and suggests trades for the next one to three days. It never places an order, it runs on fake money first, and it keeps a permanent record of every decision so it can learn from its own results. Full description: [spec.md](../spec.md).

## What M4 was for

To complete the system on top of M3's working spine: every designed job, the evening run that will operate it unattended, and the daily report you will read. It also had to fit the hard limits of the platforms it runs on (GitHub, GitHub Actions, the Claude routine, NSE).

## Words used here

| Word | Meaning |
|---|---|
| Trust scores | How much the system trusts each checklist in each market mood, learned from finished trades. |
| Confidence | The estimated chance a trade makes money. Checked regularly against what actually happened. |
| Losing-run brake | Your limit: risk is halved when the account falls 10% below its highest, and new buys pause for 10 trading days at 15%. |
| Shadow trade | A skipped candidate, settled by the same rules but outside the account, so the system can suggest whether it is skipping good trades. |
| Replay | Running the system over past days into a practice folder, never the real record. |

## What M4 built

| Part | What it does |
|---|---|
| All three checklists | Quiet breakout, Pullback in an uptrend, Gap up that holds, as approved, each a readable file in `config/checklists/`. |
| Learn | Turns finished trades into trust scores and confidence. Every figure is a range when results are unknown. Switches a checklist off in a mood once even its best case loses. Checks whether stated confidence matched reality. Every version lists the trades behind it. |
| Decide | Ranks candidates by expected result, gives each buy a confidence, skips switched-off checklists, applies the losing-run brake. Size still comes only from your limits. |
| Claude's review | The routine's instructions ([routines/review.md](../../routines/review.md)), and the code check its review must pass. Objections are recorded but not obeyed during paper trading. |
| The evening run | `propose` (fetch, clean, settle, learn, analyze, decide) and `finalize` (check the review, record decisions, write the report). It catches up missed evenings, waits for NSE until 9pm, recognises holidays and weekends, and follows renamed shares. Running either part twice does nothing the second time. |
| The daily report | Plain English: the orders for tomorrow, open positions and their exits, what finished today, and system health. Saved as `data/reports/<month>/<date>.md`. |
| Platform limits | [constraints.md](../design/constraints.md): every limit, and how the design stays inside it. Data now goes **one file per month**, and a test fails if any data file passes 25 MB (GitHub blocks at 100 MB). |

**88 automatic tests, all passing.** 31 are new, covering Learn's rules, the brake, the review check, catch-up and recovery, finalize, renames, and the new checklists.

## Checked on real data

- **A full replay, April 2024 to October 2026** (627 trading days, about 3.5 minutes):
  - 922 buys across all three checklists and all three moods;
  - every limit held, every result links to its decision;
  - Learn wrote 616 trust versions and switched off one pairing (pullbacks in a down market);
  - it judged confidence **honest** over 903 trades.
- **Live against NSE today, a Sunday**, on a copy of the data: holidays, symbol changes and corporate actions fetched; the day correctly treated as closed; Friday caught up.
- **Sizes:** the largest monthly file is 6.9 MB. A year of running adds about 25 MB to the repo, compressed.

**An honest flag.** During the replay, the losing-run brake engaged: the practice account fell more than 15% below its highest and spent long stretches at half risk, with costs still at zero. That is the brake working as designed, but it also suggests the checklists may not have an edge. Whether they do is exactly M5's question. M5 runs a proper backtest over 2015–2026 and is a go/no-go: if no checklist makes money, I stop and bring options rather than start paper trading.

## Problems found and fixed during M4

| Problem | Fix |
|---|---|
| Analysis records would have reached about 75 MB a year in one file, near GitHub's 100 MB block | One file per month for every store, and a size test |
| A rescaled trade (after a split) would have had its result worked out against the pre-split stop | Settle records each exit's result itself; Record uses that |
| An interrupted evening could have left a day cleaned but never settled | Pending days are worked out from the notebook's own record (decision 0013) |
| NSE's rename list includes renames from 2010; NSE reuses symbols, so applying them would graft one company's history onto another | A rename applies only if the old symbol stopped trading shortly before it |
| My M3 report said 692 trading days; three were corporate-action downloads | Corrected to 689 |

## Calls made by Claude during M4 (logged in [decisions/](../decisions/))

## Decision made (by you, 2026-10-11): the daily report

A real example, built by running the full system on 9 September 2026: [m4-sample-daily-report.md](m4-sample-daily-report.md). Every report links to [how to read the daily report](../how-to-read-the-daily-report.md).

**Revised after your first review**, which found it written for traders. Each buy now shows:
- the checklist's idea in plain words;
- every condition with that share's actual figures;
- the plan as a table of prices in rupees and real dates (NSE holidays skipped);
- how likely it is to work, and what that means in rupees;
- why that number of shares.

Sells explain what was bought, when and why, and why it is being sold. Every section says what it is for and whether you need to act.

Claude's two comments in it were written for this sample from the system's own figures, since the review routine starts in M6. No objection appears because none was warranted; an objection would show as a quoted line marked "recorded, not obeyed".

**Approved** after one revision. Reports are kept in `data/reports/<month>/<date>.md`, linked from the README. Moving them to `docs/` was considered and declined: the evening run may only write to `data/`, and that rule is what keeps it from changing code or documents.
