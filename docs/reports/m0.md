# M0 Report: Foundations and data check

**Finished:** 2026-10-11

## The project, in two lines

A system that studies the Indian share market each evening and suggests trades for the next one to three days. It never places an order, it runs on fake money first, and it keeps a permanent record of every decision so it can learn from its own results. Full description: [spec.md](../spec.md).

## What M0 was for

To answer, before any real building: does the market data exist, can we fetch it every day, and where can the system run unattended? Then to lay the foundations: the folders, and the automatic checks that enforce the project's rules.

| Word | Meaning |

| `main` | The repo's official version. What is on `main` is what runs. |

## What M0 built

1. **The folder layout.** One folder per job's code, and a `data/` folder that is the system's memory. Each part of the memory has exactly one job allowed to write it. Details: [design/repo-structure.md](../design/repo-structure.md).
2. **A gatekeeper for the memory** (`src/trader/store/`). All writing goes through it. It refuses if a job writes outside its own folder, and it never changes or deletes anything already written. It can only add.
3. **A commit check** (`src/trader/store/guard.py`). Before anything is saved to the repo, it confirms that no existing record was altered or removed.
4. **22 automatic tests**, all passing. They fail if any code breaks the project's rules: writing files without the gatekeeper, one job reaching into another's code, or the report trying to write.
5. **Automatic checks on GitHub.** The tests and the commit check run on every push. Every push so far has passed.
6. **A decisions log** ([decisions/](../decisions/)): every call Claude made during M0, with the reason.

## What M0 found

| Question | Answer |
|---|---|
| Does the data exist? | **Yes.** NSE publishes daily price files back to 2000 and corporate actions back to at least 2008. |
| Can GitHub Actions fetch it? | **Yes**, all of it. |
| Can Anthropic's cloud fetch it? | **No.** Its internet access is limited to a short list of sites, and NSE is not on it. |
| Can a cloud routine be restricted to a few safe commands? | **No.** The settings for this did not hold in testing. |
| Can a cloud routine save to the repo? | **Yes**, after you installed the Claude GitHub App. Verified. |

Two findings that shape later designs:
- **Today's index lists would bias a backtest.** 222 of 2019's 500 most-traded shares are not in today's Nifty 500, including collapses like Jet Airways and DHFL. A test on today's list would never see them.
- **A share's ID can change** after a split or a merger. Clean must recognise it as the same company.

## What changed as a result

The original plan had a cloud routine do everything. Because the cloud cannot reach NSE and cannot be restricted, the work is now split:

| Step | Runs on |
|---|---|
| Fetch, Clean, Analyze, Decide | GitHub Actions, every evening |
| Claude writes the case for each trade, and may veto one | Cloud routine; it saves only to a side branch, never to `main` |
| Check Claude's review, then Record, Settle, Learn | GitHub Actions |

Only Claude's review file is taken from its side branch, and only after a code check. So nothing else Claude does can reach the record. If no review arrives, the system carries on without one.

## Decisions made (approved 2026-10-11)

| Decision | Choice | Why |
|---|---|---|
| Where it runs | As above | The only setup that can reach the data and keep Claude contained. |
| Data source | NSE only | Every share we would trade is on NSE. BSE can be added later. |
| Which shares | Top 500 by trading value, recalculated monthly from NSE's own files | Even the 500th share trades about ₹25 crore a day, so fake trades stay realistic. Five times more candidates than the top 100 gives Learn more evidence. Building the list by rule avoids the index bias above. |
| GitHub App | Installed on this repo | Lets Claude's review reach the repo. |
