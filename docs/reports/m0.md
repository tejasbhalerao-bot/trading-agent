# M0 Report — Foundations and data check

**Date:** 2026-10-11
**Verdict:** The data exists and can be fetched every day. But Anthropic's cloud cannot do the fetching, and its tool limits do not hold. One change to where the daily run happens fixes both, and needs your approval because it changes the approved design.

---

## What was built

- The repo laid out as designed in [design/repo-structure.md](../design/repo-structure.md).
- `store/`: the only code that writes to `data/`. Each job can write only its own folder, and can only add files or append lines.
- The commit check: under `data/`, nothing may be changed or removed. The daily run's version also refuses any change outside `data/`.
- 22 rules tests, all passing. They fail the build if:
  - any code outside `store/` writes a file or runs a shell command;
  - one job imports another;
  - the report code asks for write access.
- GitHub checks run all of this on every push. They have passed on every push so far.
- A decisions log in [docs/decisions/](../decisions/) (4 entries).

## What was tested, and what happened

| Question | Answer |
|---|---|
| Does the data exist? | **Yes.** NSE daily price files back to 2000 (old format to July 2024, new format from January 2024; the overlap lets the two readers be checked against each other). NSE corporate actions back to at least 2008. Index lists. BSE daily files. |
| Can your laptop fetch it? | **Yes**, every NSE and BSE source. Yahoo refused (rate limit); not needed. |
| Can Anthropic's cloud fetch it? | **No.** Its network only allows a fixed list of sites (package registries, Anthropic). NSE, BSE and Google are blocked. |
| Can GitHub Actions fetch it? | **Yes**, every NSE and BSE source, and it pushed its results back to the repo. |
| Can a cloud routine push to the repo? | **No.** The Claude GitHub App is not installed on this repo. The routine could read it (the repo is public) but not write to it. |
| Can a cloud routine be limited to two commands? | **No.** `allowed_tools` turned out to be an auto-approve list, not a limit. A separate block list (`disallowed_tools`) blocked some things (editing README, `rm`) but missed others (writing into `src/`). A block list can never express "only these two commands" anyway. |
| Does NSE confirm splits in its price files? | **No.** On a split day it does not restate the previous close. Clean will instead check that the price drop matches the announced split. |

Two more findings for later designs:
- **Today's index lists are biased for backtesting.** 222 of 2019's 500 most-traded shares are not in today's Nifty 500, including Jet Airways, DHFL and Reliance Capital. A backtest using today's list would never see those collapses.
- **A share's ID can change.** Some shares get a new ISIN after a split (HEG is one), and names change on mergers. Clean must track a company across these changes.

## Proposed change: GitHub Actions does the work, Claude only reviews

| Step | Where | Why |
|---|---|---|
| Fetch, Clean, Analyze, Decide (evening) | GitHub Actions, on a schedule | Can reach NSE. Plain code on a plain machine. Free for a public repo. |
| Claude's written case and veto | Cloud routine | Needs no market data, only today's proposals from the repo. Pushes its review to a branch of its own, never to `main`. |
| Check the review, then Record, Settle, Learn, report | GitHub Actions, on a schedule | Takes **only the review file** from Claude's branch and checks it. Anything else on that branch is ignored. If no review arrives, it carries on without one. |

**Why this is better than the approved design, not just a workaround.**
- The safety no longer depends on limiting what Claude can do in its session, which turned out not to be possible. Claude's output can only reach the record through a check written in code.
- "Nothing waits for you" now also means nothing waits for Claude.

**How `main` is protected.** This is the replacement for the tool limits:
1. A GitHub rule on `main` (free for public repos) blocks pushes from everyone except you and the finalize step.
2. The finalize step pushes with a key that GitHub only releases to workflows running from `main`. So a workflow added on Claude's branch cannot get that key.

Each of these is tested before anything relies on it. Setting them up means changing repo settings, which you will do yourself from step-by-step instructions, or approve one at a time. That happens in M6, not now.

**What changes in the approved structure:** only where the run happens and how Claude's review arrives. The folders, owners and rules stay the same.

## Decisions for you

### 1. Approve the change above
**Recommendation: approve.** The alternative is to switch the cloud environment to full internet access, which you would do in claude.ai settings, and hope NSE doesn't block Anthropic's servers. That still leaves the tool-limit problem with no fix.

### 2. Install the Claude GitHub App on this repo
Needed for Claude's review to reach the repo at all. The link is https://github.com/apps/claude/installations/select_target. Grant it **this repo only**. If you would rather not, the system runs rules-only: no written case and no veto.

### 3. Data source
**Recommendation: NSE only** (daily price files plus corporate actions). Every candidate share trades on NSE, and NSE is the more active market.
**Alternative:** also use BSE as a second source for Clean to compare prices against. It is more work, and the two exchanges' prices legitimately differ a little. It can be added later if Clean needs it.

### 4. Which shares to watch

Median daily trading value per share over the last 60 trading days:

| Rank | Median daily value |
|---|---|
| 1 | ₹1,907 crore |
| 100 | ₹197 crore |
| 200 | ₹100 crore |
| 500 | ₹25 crore |
| 1,000 | ₹6 crore |

Even the 500th share is far bigger than any retail order, so paper fills on either list predict real fills reasonably well.

| | Top 100 | Top 500 (recommended) |
|---|---|---|
| Candidates per day | Fewer | About 5× more, so Learn gets enough evidence within the paper period |
| Data cleaning | Least work | More corporate actions to handle |
| Price limits | Mostly shares without fixed daily price limits | Some smaller shares hit a daily price limit; a real order may not fill that day, so Settle marks those "don't know" |

**How the list is built: recommended by rule, not from the index.** Each month, take the top shares by median trading value over the previous 60 days, using NSE's own files. The same rule then works for live trading and for the backtest, with no bias from today's index. The cost: the list differs slightly from the official Nifty 500.

**Liquidity floor:** the rule above sets it automatically (about ₹25 crore a day at rank 500).
